PRODUCT IN ONE SENTENCE
-----------------------
OJT Intern Path is a multi-tenant web platform that connects schools, companies,
and student interns for internship discovery, school endorsement, company hiring,
school–company agreements (MOAs), OJT hour logging, assessments, KPIs, reports,
and certificates — with subscription billing via PayMongo.

1. HIGH-LEVEL ARCHITECTURE
================================================================================

Monorepo-style layout:

  CAPSTONE/
    src/                     Vue 3 SPA (frontend)
    backend/                 Laravel 12 API + can also serve built SPA from public/
    package.json             Frontend npm scripts
    .env                     Frontend Vite env (VITE_API_BASE_URL)
    scripts/stage-frontend.ps1
                           Copies dist/ → backend/public/

Pattern:
  - Frontend talks to Laravel REST API under /api
  - Auth = Laravel Sanctum personal access tokens (Bearer)
  - Not a classic cookie SPA session as primary auth
  - Organizations (school | company) are tenants; users have memberships + roles

Typical local run (TWO processes):
  1) backend:  php artisan serve --host=127.0.0.1 --port=8000
  2) root:     npm run dev   → http://127.0.0.1:5173
  Frontend .env: VITE_API_BASE_URL=http://127.0.0.1:8000/api
  Backend .env:  APP_URL=http://127.0.0.1:8000
                 FRONTEND_URL=http://127.0.0.1:5173
                 DB_CONNECTION=sqlite (default in many local setups)

Production-ish local (SPA served by Laravel):
  npm run build
  npm run deploy:backend-public   # stages dist into backend/public
  php artisan serve
  Then open http://127.0.0.1:8000 — if VITE_API_BASE_URL was empty at build time,
  API calls use same-origin /api (works). If set to absolute URL, that is baked in.

3. USER ROLES (APP-LEVEL)
================================================================================

User.role (app routing role) values:
  admin | company | school | student | guest | null

Post-login dashboards:
  admin   → /admin/overview
  company → /dashboard
  school  → /school
  student → /intern   (product language: Intern)
  guest   → /guest

Important naming caveat:

  - UI routes say /intern and "Intern"

5. CORE DOMAIN FLOWS
================================================================================

A) INTERNSHIP / APPLICATION PIPELINE
  Company posts internship (flexible schedule fields supported).
  Student applies.
  School endorses or rejects (endorsements).
  Company accepts/rejects endorsed applicants.
  Statuses roughly: submitted/pending → endorsed → accepted | rejected | school_rejected

B) AGREEMENTS (formerly Contracts)
  School ↔ Company partnership documents / MOAs.
  User-facing term: Agreement. Routes: /agreements (alias /contracts).
  API: /api/agreements (canonical) and /api/contracts (legacy aliases).
  DB: migration may rename contracts → agreements; models dual-table aware.
  Amendment: PATCH .../amend → status pending_amendment; both sides re-approve pattern.
  Types: agreement-types / contract-types.

C) FLEXIBLE INTERNSHIP SCHEDULE
  Fields on internships: schedule_type, weekly_hours, schedule_days, time_in/out,
  timezone, is_flexible (+ legacy free-text schedule).

D) INTERVIEWS
  ApplicationInterview model + InterviewController
  UI: ApplicationInterviewPanel.vue on company/school applicant views

E) OJT LOGS / HOURS
  Real API OjtLogController (not localStorage-only).
  Student logs hours; company/school approve.
  Dept head can monitor progress (org.view_ojt_progress).
  UI: OJTHours.vue + school reports/progress panels.

F) ASSESSMENTS
  ApplicationAssessment — scored/stage assessments on applications.
  UI: ApplicationAssessmentPanel.vue

G) KPI / REPORTS / CERTIFICATES
  GET /api/reports/kpi
  GET /api/reports/export?type=placements|ojt|assessments
  Certificates generate/download
  Wired into School/Company dashboards and school reports view

H) SUBSCRIPTIONS / PAYMONGO
  Plans: free | standard | premium (SubscriptionPlanDefinition)
  Org billing page: /billing (OrganizationSubscription.vue + SubscriptionManager.vue)
  Paid upgrade: POST /subscriptions/checkout → PayMongo → return → POST /subscriptions/verify
  Pending checkout stored in organization.settings.pending_plan_change
  Cancel pending supported in UI; stuck pending can be replaced on new checkout
  Unpaid status=pending orgs get FREE limits until verify (SubscriptionPlanService)
  Active orgs keep current plan during checkout (status not forced to pending if already active)
  Requires PAYMONGO_SECRET_KEY in backend .env

I) SCHOOL STUDENT ACCOUNTS
  /school/students — temporary student logins, roster, setup links

9. AUTH FRONTEND FLAG
================================================================================

src/config/auth.ts:

11. HOW TO RUN / FIX COMMON ERRORS
================================================================================

FIRST TIME BACKEND:
  cd backend
  # enable php zip extension if composer fails on Windows/XAMPP
  composer install
  copy .env.example .env   # if needed
  php artisan key:generate
  php artisan migrate
  php artisan db:seed

DAILY DEV:
  Terminal A: cd backend && php artisan serve --host=127.0.0.1 --port=8000
  Terminal B: cd CAPSTONE && npm run dev
  Open: http://127.0.0.1:5173/

Error: "Cannot reach the API server. Set VITE_API_BASE_URL..."
  Means Laravel is not running OR wrong VITE_API_BASE_URL OR Vite not restarted
  after .env change. Fix:
    1) Start artisan serve on :8000
    2) Root .env: VITE_API_BASE_URL=http://127.0.0.1:8000/api
    3) Restart npm run dev
    4) Confirm GET http://127.0.0.1:8000/api/subscription-plans returns JSON

UI changes not showing when using artisan-served SPA:
  Source in src/ is not live — rebuild:
    npm run build && npm run deploy:backend-public
  Or use npm run dev for HMR.

PayMongo upgrades:
  Set PAYMONGO_SECRET_KEY in backend/.env
  Use /billing while logged in as school or company admin

12. DATA MODEL (SIMPLIFIED)
================================================================================

User
  ├─ platformRole (optional, admin)
  ├─ organizationMemberships → Organization + Role + permissions
  ├─ school | company | student profile rows

Organization (type: school|company)
  ├─ subscription (plan, status, billing_cycle)
  ├─ settings.pending_plan_change (PayMongo pending)
  ├─ roles, memberships

School / Company
  └─ owned by user + linked to organization

Internship (company or school hosted)
  └─ Applications
       ├─ Interviews
       ├─ Assessments
       ├─ OjtLogs
       └─ Certificates

Agreement (MOA between school & company orgs)
  └─ type, status (pending, active, pending_amendment, rejected, cancelled...), amend fields

13. CONVENTIONS FOR FUTURE AI WORK
================================================================================

- Prefer additive changes; do not break working application/agreement flows
- User-facing: say "Agreement" not "Contract" (keep API aliases if needed)
- School-first redesigns often share TenantRbac / SubscriptionManager with Company
- Do NOT edit plan files in .cursor/plans unless user asks
- Do NOT commit unless user asks
- After UI changes for artisan-served mode: build + deploy:backend-public
- Keep PayMongo as payment provider unless user explicitly changes it
- AUTH_DISABLED should stay false unless debugging
- Ask before large design assumptions; match existing Tailwind/shadcn patterns
- When serving via Laravel public/, remember Vite source ≠ live assets until rebuild
