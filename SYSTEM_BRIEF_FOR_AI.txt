PRODUCT IN ONE SENTENCE
-----------------------
OJT Intern Path is a multi-tenant web platform that connects schools, companies,
and student interns for internship discovery, school endorsement, company hiring,
school–company agreements (MOAs), OJT hour logging, assessments, KPIs, reports,
and certificates — with subscription billing via PayMongo.

1. HIGH-LEVEL ARCHITECTURE
================================================================================

Monorepo-style layout:

  CAPSTONE/
    src/                     Vue 3 SPA (frontend)
    backend/                 Laravel 12 API + can also serve built SPA from public/
    package.json             Frontend npm scripts
    .env                     Frontend Vite env (VITE_API_BASE_URL)
    scripts/stage-frontend.ps1
                           Copies dist/ → backend/public/

Pattern:
  - Frontend talks to Laravel REST API under /api
  - Auth = Laravel Sanctum personal access tokens (Bearer)
  - Not a classic cookie SPA session as primary auth
  - Organizations (school | company) are tenants; users have memberships + roles

Typical local run (TWO processes):
  1) backend:  php artisan serve --host=127.0.0.1 --port=8000
  2) root:     npm run dev   → http://127.0.0.1:5173
  Frontend .env: VITE_API_BASE_URL=http://127.0.0.1:8000/api
  Backend .env:  APP_URL=http://127.0.0.1:8000
                 FRONTEND_URL=http://127.0.0.1:5173
                 DB_CONNECTION=sqlite (default in many local setups)

Production-ish local (SPA served by Laravel):
  npm run build
  npm run deploy:backend-public   # stages dist into backend/public
  php artisan serve
  Then open http://127.0.0.1:8000 — if VITE_API_BASE_URL was empty at build time,
  API calls use same-origin /api (works). If set to absolute URL, that is baked in.

Frontend checks:
  npm run type-check
  npm run build
  npm test   (vitest; navigation permission tests live in src/layouts/navigation.test.ts)

3. TWO ROLE LAYERS (READ THIS BEFORE CHANGING ACCESS)
================================================================================

There are two different "role" concepts. Most access bugs come from treating
them as one.

A) APP WORKSPACE ROLE
  User.role / User::effectiveAppRole() is only:
    admin | school | company | student | guest | null
  This chooses the workspace shell and the route's requiresRole.

  effectiveAppRole() (backend/app/Models/User.php):
    - platform admin → admin
    - school-org membership with slug intern or student_member → student
    - school-org membership with no role slug, if the user has a student row → student
    - EVERY other school-org membership → school
      (School Admin, Department Head, Teacher, Registrar, custom subuser)
    - any company-org membership → company
    - otherwise users.role, with guest stored as null

  Post-login landing (src/router/index.ts getRoleDashboard):
    admin   → /admin/overview
    student → /intern   (product language: Intern; API/DB role is often "student")
    guest   → /guest
    school  → first school nav page the membership permissions allow, else /settings
    company → first company nav page the membership permissions allow, else /settings

  There is no ojt_admin slug and no "OJT Office" role. "CvSU OJT Office" is the
  display name of the primary school account (school@cvsu.edu.ph). Its membership
  role is School Admin.

B) ORGANIZATION MEMBERSHIP ROLE
  organization_memberships.role_id points at a tenant role.
  Effective permissions = role permission keys ∪ grants − denies.
  GET /api/auth/me returns them on memberships[0].permissions.
  The frontend reads memberships[0] only (same as hasPermission()).
  After a permission save, the subuser must log out and back in so /auth/me
  reloads that list.

GLOBAL SEEDED SLUGS (RbacSeeder) vs TENANT DEFAULT SLUGS (TenantRoleService)
  Platform: system_admin, platform_super_admin, platform_support_admin
  School global: school_admin, school_department_head, student_member
  Company global: company_admin, company_hr_manager

  New school tenants also get (TenantRoleService::defaultDefinitionsForType):
    school_admin, department_head, teacher, registrar, intern
  New company tenants also get:
    company_admin, manager, hr, finance

  The demo department head uses the GLOBAL slug school_department_head,
  not the tenant slug department_head. Do not merge or rename those slugs
  unless a task explicitly says so.

DEFAULT SCHOOL ROLE PACKS (OrgPermissions + TenantRoleService)
  School Admin: full org catalog, including manage students, roles, subscription,
    internships, agreements, applications, OJT, reports, export, certificates.
  Department Head: view/approve applications, view students, view/approve OJT,
    reports including export, agreements, certificates, assessments, profile.
    No manage_students, no manage_roles, no manage_subscription.
  Teacher: org.view_students, org.view_ojt_progress, org.view_applications,
    org.view_reports, org.reports_view, view_reports, upload_files, manage_profile.
    manage_profile does NOT grant course-hour management or org required-hours edits.
  Registrar: view/manage students, reports, manage_users, upload_files.
  Intern (membership slug intern): upload_files only, and effectiveAppRole is student.

DEFAULT COMPANY ROLE PACKS
  Company Admin: members, roles, subscription, internships, agreements,
    applications, approve OJT logs, assessments, reports, export, certificates.
    Does not include org.view_students (that is a school roster key).
  HR: internships, agreements, applications, approve OJT, assessments, reports.
    No roles, no subscription.
  Manager: internships, applications, reports (narrower than HR).
  Finance: agreements, reports, subscription.

PERMISSION CATALOG (canonical org.* keys)
  View:     org.view_internships, org.view_agreements, org.view_applications,
            org.view_students, org.view_ojt_progress, org.view_reports
  Manage:   org.manage_internships, org.manage_agreements, org.manage_applications,
            org.manage_students, org.manage_assessments, org.manage_members,
            org.manage_roles, org.manage_subscription, org.manage_profile
  Reports:  org.reports_view, org.reports_export
  Approve:  org.approve_applications, org.approve_agreements, org.approve_ojt_logs,
            org.approve_certificates
  Legacy keys still exist and are separate toggles in the matrix:
    manage_users, manage_roles, manage_permissions, view_reports, upload_files,
    manage_subscription, manage_profile, manage_internships, manage_contracts,
    review_applications, org.manage_contracts, org.review_applications, org.manage_members

  Catalog:  backend/app/Support/OrgPermissions.php
  Gate:     backend/app/Services/PermissionGate.php
  Frontend alias helper (in-page buttons): src/services/permissions.ts
  UI:       /access/roles and /access/permissions → TenantRbac.vue
            OrganizationAccessManager.vue exists but is unused. Do not wire it
            unless asked.

School and company sidebars used to be a hardcoded list for everyone with
effectiveAppRole school or company. Limited subusers still saw and could open
every page. That is fixed.

Source of truth: src/layouts/navigation.ts
  visibleNavItems(), assignedPermissionAllows(), firstAllowedOrgPath(),
  routePermissionRequirements()

Admin and student menus are not filtered this way.
Pending or rejected organizations still only see Verification, Notifications,
and Settings (pendingOrganizationNavItems). Settings itself is always available.

  Endorsements (/school/endorsements) and Applicants (/dashboard/applicants)
      org.view_applications, org.manage_applications, org.approve_applications,

  Reports

      org.view_ojt_progress, org.approve_ojt_logs

Students and platform admins can still open /ojt-hours. The permission check
runs only when the signed-in app role is school or company.

If a school/company user has no allowed nav item, landing is /settings.
Direct navigation to a disallowed named route redirects to the first allowed
page. Verified with depthead@cvsu.edu.ph: Student Accounts, Role Management,
Permissions, and Subscription are hidden; /school/students and /access/roles
return to /school. School Admin still sees the full menu.

BACKEND ALIASES STILL EXIST — do not delete them unless a task says so.
PermissionGate::ALIASES can let an API succeed when a related key is still on,
even if the checkbox the user thinks they turned off is off. Examples:
  org.view_ojt_progress  also satisfied by view_reports, org.view_reports,
                         org.view_students
  org.view_students      also satisfied by manage_users, org.manage_members
  application view/manage/approve also satisfied by review_applications
  org.reports_export     aliases ONLY itself (bleed fix; keep it)
  org.approve_certificates aliases ONLY itself (bleed fix; keep it)
Turning off only one of the three report keys (org.view_reports,
org.reports_view, view_reports) still leaves Reports visible.

ALREADY FIXED AND SHOULD STAY FIXED
  view_reports does not grant org.reports_export or org.approve_certificates.
  manage_profile does not allow PATCH of organization-wide required OJT hours.
  That setting requires org.approve_ojt_logs.
  ReportExportController 403 returns JsonResponse (union type includes it;
  a missing JsonResponse previously became a TypeError 500).

6. CORE DOMAIN FLOWS
================================================================================

A) INTERNSHIP / APPLICATION PIPELINE (implemented order)
  Company creates the posting in the UI (eligible courses, skills, duration
  text). School-hosted internships exist on the API; there is no school
  "create posting" screen.
  Student applies → status submitted.
  School endorses or school-rejects. Endorsement is required BEFORE interview
  and BEFORE company acceptance. API permission: org.approve_applications.
  Interview is optional and a separate record. The proposer cannot confirm
  their own proposal.
  Company accepts or rejects only after endorsement → accepted | rejected.
  OJT logs exist only after accepted.
  Duplicate application guard and duplicate agreement guard are in place.
  Statuses: submitted → endorsed | school_rejected → accepted | rejected.
  School.vue endorsement confirm snapshots the decision locally before await.
  AlertDialog emits action then close; reading pendingDecision after close
  used to throw "Cannot read properties of null (reading 'action')".

B) AGREEMENTS (formerly Contracts)
  School ↔ Company partnership documents / MOAs.
  Either side can initiate; the other accepts or rejects.
  User-facing term: Agreement. Routes: /agreements (alias /contracts).
  API: /api/agreements (canonical) and /api/contracts (legacy aliases).
  DB: migration may rename contracts → agreements; models dual-table aware.
  Amendment: PATCH .../amend → status pending_amendment; both sides re-approve.
  Types: agreement-types / contract-types.
  Creating/managing agreement types requires org.manage_agreements.

C) FLEXIBLE INTERNSHIP SCHEDULE
  Fields on internships: schedule_type, weekly_hours, schedule_days, time_in/out,
  timezone, is_flexible (+ legacy free-text schedule).
  internships.duration is display text, not the course hour requirement.
  Demo job "website development" duration is "486 hours", weekly_hours 5.

D) INTERVIEWS
  ApplicationInterview model + InterviewController
  UI: ApplicationInterviewPanel.vue on company/school applicant views

E) OJT LOGS / HOURS
  Real API OjtLogController (not localStorage-only).
  Student submits logs. Company approves each pending log in the UI.
  School OJT screen is monitoring. API permission org.approve_ojt_logs exists
  for school admin and department head, but the school UI is read-only monitoring.
  Required hours used by OJT math and certificates:
    organization settings required_ojt_hours / requiredHours if set,
    otherwise DEFAULT_REQUIRED_HOURS = 500.
  Changing the org-wide number requires org.approve_ojt_logs, not manage_profile.
  GET required hours is still school/company app role.

F) SCHOOL + COURSE REQUIRED HOURS (foundation + school-admin UI only)
  Table school_course_requirements:
    school_id, course_name, course_name_key (lowercase collapsed),
    required_hours unsigned integer >= 1, unique (school_id, course_name_key).
  applications.required_ojt_hours is a nullable unsigned snapshot.
  Null is allowed. A non-null value below 1 is rejected on save.
  Backfill (ApplicationRequiredOjtHoursBackfill) copies an explicit positive
  school org setting only. It never invents 500. Live CvSU has no org-wide
  hours configured, so the existing accepted application snapshot stays null.
  Updating a course row does NOT rewrite existing application snapshots.
  API (behind org.verified, permission org.manage_students):
    GET/POST /api/school-course-requirements
    PATCH /api/school-course-requirements/{schoolCourseRequirement}
  Settings UI (SettingsPanel.vue) shows "Course OJT Requirements" only when
  app role is school AND hasPermission('org.manage_students').
  Teacher with only manage_profile is 403. The org-wide "OJT Required Hours"
  block is still there.
  NOT WIRED, and do not change unless a task explicitly asks:
    job posting duration, application eligibility, acceptance blocking,
    OJT hour calculations, certificate hour checks, DTR, interviews, assessments.
  The settings empty state says application blocking is not active yet.

G) ASSESSMENTS
  ApplicationAssessment — scored/stage assessments on applications.
  UI: ApplicationAssessmentPanel.vue
  Wording should stay cautious; do not claim an AI decision.

H) KPI / REPORTS / CERTIFICATES
  GET /api/reports/kpi          requires org.reports_view or org.view_reports
  GET /api/reports/export       requires org.reports_export only
  Certificates:
    Issuing requires org.approve_certificates only.
    Index/download may still allow report-view permission to VIEW certificates.
    The certificate is printable HTML from CertificateController::buildCertificateHtml
    (Georgia, double #1e3a5f border, centered). It is not a generated PDF.
    A local preview file may exist at backend/public/certificate-preview.html.
    Do not treat that preview as the production download.

I) SUBSCRIPTIONS / PAYMONGO
  Plans: free | standard | premium (SubscriptionPlanDefinition)
  Org billing page: /billing (OrganizationSubscription.vue + SubscriptionManager.vue)
  Paid upgrade: POST /subscriptions/checkout → PayMongo → return → POST /subscriptions/verify
  Pending checkout stored in organization.settings.pending_plan_change
  Cancel pending (P0-03) and the pending-plan limit (P1-09) must stay as they are.
  Unpaid status=pending orgs get FREE limits until verify (SubscriptionPlanService)
  Active orgs keep current plan during checkout.
  If PAYMONGO_SECRET_KEY is empty, checkout and verify return HTTP 422
  code paymongo_not_configured BEFORE any subscription mutation.
  The UI shows an info dialog and refreshes. It does not fake success, skip
  verify, or invent a mock provider. Do not add a fake payment path.

J) SCHOOL STUDENT ACCOUNTS
  /school/students — temporary student logins, roster, setup links.
  Visible only with student-manage keys (see section 4).
  Students are school-provisioned; they use the school subscription code.

K) ORGANIZATION VERIFICATION
  School and company users with verificationStatus pending, rejected, or null
  are forced to /organization-verification until approved.
  Sub-accounts (teachers, department heads, custom subusers) often have no
  School or Company row of their own. formatUserProfile inherits verification
  from organizationSchool() / organizationCompany() (the parent org).
  Do not send them to "Awaiting organization verification" just because their
  own school/company row is null. Middleware EnsureOrganizationVerified already
  uses the parent org. Do not weaken verification.

L) FORCED PASSWORD CHANGE
  mustChangePassword still goes to Change Password, then
  authStore.refreshUser(), then the role dashboard.
  Do not skip that refresh (P0-01). The local dashboard helper does not decide
  verification; the router guard does.

12. HOW TO RUN / FIX COMMON ERRORS
================================================================================

FIRST TIME BACKEND:
  cd backend
  # enable php zip extension if composer fails on Windows/XAMPP
  composer install
  copy .env.example .env   # if needed
  php artisan key:generate
  php artisan migrate
  php artisan db:seed

DAILY DEV:
  Terminal A: cd backend && php artisan serve --host=127.0.0.1 --port=8000
  Terminal B: cd CAPSTONE && npm run dev
  Open: http://127.0.0.1:5173/

Error: "Cannot reach the API server. Set VITE_API_BASE_URL..."
  Means Laravel is not running OR wrong VITE_API_BASE_URL OR Vite not restarted
  after .env change. Fix:
    1) Start artisan serve on :8000
    2) Root .env: VITE_API_BASE_URL=http://127.0.0.1:8000/api
    3) Restart npm run dev
    4) Confirm GET http://127.0.0.1:8000/api/subscription-plans returns JSON

UI changes not showing when using artisan-served SPA:
  Source in src/ is not live — rebuild:
    npm run build && npm run deploy:backend-public
  Or use npm run dev for HMR.

Limited subuser still sees a page after permissions were turned off:
  1) Log out and back in so memberships[0].permissions refreshes.
  2) Check whether a sibling key in the same nav group is still on
     (section 4). Reports stay on if any of the three report keys remain.
  3) Backend aliases (section 4) affect API checks, not the sidebar.

PayMongo upgrades:
  Set PAYMONGO_SECRET_KEY in backend/.env
  Use /billing while logged in as a school or company user who has
  org.manage_subscription or manage_subscription.
  Empty secret → 422 paymongo_not_configured. Do not fake a successful payment.

13. DATA MODEL (SIMPLIFIED)
================================================================================

User
  ├─ platformRole (optional, admin)
  ├─ organizationMemberships → Organization + Role + permissions
  ├─ school | company | student profile rows
  └─ effectiveAppRole() is derived; it is not the membership role name

Organization (type: school|company)
  ├─ subscription (plan, status, billing_cycle)
  ├─ settings.pending_plan_change (PayMongo pending)
  ├─ settings.required_ojt_hours / requiredHours (org-wide; 500 fallback if absent)
  ├─ verification status inherited by subusers who have no own school/company row
  ├─ roles, memberships

School / Company
  └─ owned by a user + linked to organization
  School has many school_course_requirements

Internship (company or school hosted)
  └─ duration is display text
  └─ Applications
       ├─ required_ojt_hours nullable snapshot (not yet used by OJT math)
       ├─ Interviews
       ├─ Assessments
       ├─ OjtLogs
       └─ Certificates

Agreement (MOA between school & company orgs)
  └─ type, status (pending, active, pending_amendment, rejected, cancelled...), amend fields

14. CONVENTIONS FOR FUTURE AI WORK
================================================================================

- Prefer additive changes; do not break working application/agreement flows
- User-facing: say "Agreement" not "Contract" (keep API aliases if needed)
- School-first redesigns often share TenantRbac / SubscriptionManager with Company
- Do NOT edit plan files in .cursor/plans unless user asks
- Do NOT commit unless user asks
- After UI changes for artisan-served mode: build + deploy:backend-public
- Keep PayMongo as payment provider unless user explicitly changes it
- Do not fake PayMongo success, skip verify, or add a mock provider
- Do not change cancel-pending or the pending-plan limit unless asked
- AUTH_DISABLED should stay false unless debugging
- Do not rename or delete RBAC keys, and do not remove PermissionGate aliases,
  unless a task explicitly asks. Nav gating intentionally ignores cross-feature aliases.
- Do not give Teachers course-hour management just because they have manage_profile
- Do not wire course required hours into eligibility, acceptance, OJT math,
  or certificates unless a task explicitly asks
- Do not invent an "OJT Office" or ojt_admin role
- Forced password change must still refresh the user before routing
- Subusers inherit parent organization verification
- Ask before large design assumptions; match existing Tailwind/shadcn patterns
- When serving via Laravel public/, remember Vite source ≠ live assets until rebuild
